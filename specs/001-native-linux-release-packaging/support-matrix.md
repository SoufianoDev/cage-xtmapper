## Status rules

- **Supported** — build, package metadata, dependency resolution, lifecycle, executable startup and required host/session integration tests all pass for the exact row.
- **Experimental** — a candidate exists and some CI/package gates pass, but required lifecycle/runtime/target-host proof remains missing.
- **Unavailable** — no viable artifact has been built and validated for that exact format/target cell.

**No target is Supported yet.** The latest successful target audit proves repeatable target builds, ELF/dependency inspection, package dependency solving and package-manager lifecycle inside containers. The separate multi-architecture validation run confirms the amd64 and arm64 ELF builds. It does not prove Cage XtMapper starts correctly inside a real Wayland/graphics session, or that Waydroid input, device permissions and privilege/transport integration work.

## Evidence interpretation

The audited container images are pinned by digest. Arch's 2026-10-27 archive path returned HTTP 404, so the workflow uses the available 2026-10-26 snapshot and records that value in environment.txt. The Debian target records the version file value 13.7. Ubuntu's /etc/debian_version reports Debian-base codenames rather than an Ubuntu point release; the Ubuntu version is therefore taken from /etc/os-release (24.04.5 LTS / 26.04.1 LTS).

The Debian/Ubuntu .deb builds use dpkg-shlibdeps; Fedora RPM requirements are generated from the actual ELF; Arch maps SONAMEs to installed package owners; Alpine's APK metadata declares detected so: dependencies. Full direct dependencies, symbol-version records and transitive loader reports are in each target artifact and in [library-decision-table.md](./library-decision-table.md). No current portable archive bundles shared .so files.

The candidate .deb, .rpm, Arch and .apk artifacts from branch CI are retained as GitHub Actions artifacts. The tag-triggered release workflow is now configured to build versioned candidates and attach them, checksums and a status index to a clean draft release. That release workflow has not yet been exercised by a tag push; therefore release attachment and the index are not end-to-end verified. The current bootstrap installer still uses the legacy .tar/helper path and does not dispatch native package-manager installation. Existing non-empty draft releases and published releases are deliberately not modified. SHA-256 files provide integrity checks, not publisher authentication. Alpine candidate signing uses an ephemeral CI key, and no production signing keys or package repositories were created or published.
